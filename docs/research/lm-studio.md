# ผลค้นคว้า: LM Studio (แอปที่แนะนำ)

ค้นเมื่อ 2026-10-18 จากแหล่งของ LM Studio เอง (lmstudio.ai docs, blog, changelog, terms, privacy, GitHub `lmstudio-ai/localization`, ซอร์สปลั๊กอิน `lmstudio/rag-v1`)
ป้าย **[ยืนยันแล้ว]** = เห็นในแหล่งต้นทาง / **[ยังไม่ยืนยัน]** = ไม่พบในเอกสารทางการ ต้องเช็กกับแอปจริง

---

## สรุปสั้น: เรื่องที่ขัดหรือต้องแก้ใน PRD

1. **UI ภาษาไทยมีจริง แต่แปลไม่ครบ** ข้อความในแอปที่เป็นไทยมีราว 71% (1,028 จาก 1,442 ข้อความ) และไฟล์ภาษาไทยไม่ได้อัปเดตตั้งแต่ มิ.ย. 2025 จึงจะเห็นภาษาอังกฤษปนอยู่ด้วย ถ้าคู่มือแคปหน้าจอเป็นไทยต้องระวังเรื่องนี้ (PRD §7)
2. **การแนบเอกสารส่วนใหญ่จะใช้ RAG แทนการใส่ทั้งฉบับ** แอปจะใส่เอกสารทั้งฉบับก็ต่อเมื่อเอกสารรวมกับคำสั่งยาวไม่เกินราว 70% ของ context ที่ยังว่าง ถ้า context เป็น 4096 (น่าจะเป็นค่าเริ่มต้น แต่ยังไม่ยืนยัน) เอกสารไทยยาวแค่ 1–2 หน้าก็เกินแล้ว ผลคือโมเดลเห็นเอกสารแค่บางท่อน (ค่าเริ่มต้น 3 ท่อน) ในแอปไม่มีปุ่มบังคับให้ใส่ทั้งฉบับ วิธีเดียวคือเพิ่ม context length ให้ยาวขึ้น
3. **"ค่าเริ่มต้นของ LM Studio" ไม่ได้เหมือนกันทุกโมเดล** โมเดลในแคตตาล็อกของแอปตั้งค่า sampling ของตัวเองไว้ใน model.yaml และผู้ใช้ก็ตั้งค่าแยกรายโมเดลได้ ถ้าจะให้ทุกโมเดลรันในเงื่อนไขเดียวกัน (PRD §6.3) สคริปต์ต้องกำหนด temperature, top_p, top_k, max tokens และ context length เองทุกครั้ง ไม่ควรพึ่งค่าเริ่มต้น
4. **ป้ายบอกว่าโมเดลลงเครื่องได้ไหมมี 4 ป้าย ไม่ใช่ 3 สี** ป้ายในแอปเป็น "ค่าประมาณ" ที่แอปเขียนกำกับเองว่าอาจผิด เอกสารทางการไม่ได้บอกว่าแต่ละป้ายเป็นสีอะไรหรือคำนวณอย่างไร (ดูข้อ 2 ด้านล่าง)
5. **บริษัทออกแอปใหม่ชื่อ "LM Studio Bionic" (เปิดตัว ก.ค. 2026)** เป็นคนละแอปกับ LM Studio ตอนนี้หน้าแรกของ lmstudio.ai ชี้ไปดาวน์โหลด Bionic เป็นหลัก มือใหม่จึงอาจโหลดผิดตัว คู่มือควรให้ลิงก์ตรงไปที่ `lmstudio.ai/download` และบอกว่าต้องเลือก "LM Studio" ไม่ใช่ Bionic
6. **ในเงื่อนไขการใช้ (terms) ฉบับปัจจุบันไม่มีคำว่า "ฟรี"** แต่อนุญาตให้ใช้ "ส่วนตัวและ/หรือในธุรกิจภายใน" และระบุว่ามีบางฟีเจอร์ที่เสียเงิน (เช่น โมเดลบนคลาวด์) ส่วนประกาศฟรีสำหรับงานยังอยู่บนเว็บ (blog 8 ก.ค. 2025) PRD §7 ข้อ "ฟรีสำหรับใช้ในงาน" จึงยังถูก แต่ควรอ้าง blog เป็นหลักฐาน
7. **ความต้องการขั้นต่ำ: แอปแนะนำ RAM 16GB** เครื่องเล็กที่มี RAM 8GB ต่ำกว่าที่แอปแนะนำ (แต่เป็นคำแนะนำ ไม่ใช่ขั้นต่ำบังคับ)

## 2. ป้ายบอกว่าโมเดลลงเครื่องได้ไหม (fit indicator)

ป้ายนี้อยู่ในหน้าเลือกไฟล์ quantization ตอนดาวน์โหลด ข้อความด้านล่างมาจากไฟล์แปลภาษาของแอปเอง (`discover.json`) [ยืนยันแล้ว]
https://github.com/lmstudio-ai/localization/blob/main/en/discover.json , https://github.com/lmstudio-ai/localization/blob/main/th/discover.json

| ป้าย (อังกฤษ) | ป้ายใน UI ภาษาไทย | ความหมายตามคำอธิบายในแอป |
|---|---|---|
| Full GPU Offload Possible | สามารถใช้ GPU แบบเต็มรูปแบบ | โมเดลน่าจะใส่ลงหน่วยความจำการ์ดจอได้ทั้งตัว ทำให้เร็วขึ้นมาก |
| Partial GPU Offload Possible | สามารถใช้ GPU แบบบางส่วน | ใส่ลงหน่วยความจำการ์ดจอได้บางส่วน ส่วนที่เหลือใช้ RAM |
| Likely Fit | น่าจะพอดี | น่าจะใส่ลง RAM ของเครื่องได้ (รันด้วย CPU หรือไม่ใช้การ์ดจอ) |
| Likely too large | อาจใหญ่เกินไปสำหรับเครื่องนี้ | อาจต้องใช้หน่วยความจำเกินที่เครื่องมี แอป**ไม่แนะนำ**ให้ดาวน์โหลด |

- ทุกป้ายมีคำเตือนกำกับว่า "อาจมีปัจจัยอื่นๆ ที่ทำให้โหลดไม่ได้ เช่น สถาปัตยกรรมของโมเดล ความสมบูรณ์ของไฟล์โมเดล หรือหน่วยความจำที่มีในคอมพิวเตอร์ของคุณ" แปลว่าป้ายเป็นแค่ค่าประมาณ ไม่ได้รับประกัน
- **ป้ายไม่ได้บอกความเร็ว** ป้าย "น่าจะพอดี" แปลว่าโหลดได้ ไม่ได้แปลว่าตอบเร็วพอ ซึ่งต่างจากเกณฑ์ "ใช้งานได้จริง" ของเว็บเรา (ประมาณ 5 token/วินาทีขึ้นไป) คู่มือควรเขียนแยกสองเรื่องนี้ให้ชัด
- **สีของแต่ละป้าย** [ยังไม่ยืนยัน] ไม่มีในเอกสารหรือไฟล์แปล ต้องดูจากแอปจริง
- **วิธีคำนวณ** [ยังไม่ยืนยันในรายละเอียด] เอกสารไม่ได้อธิบายสูตรของป้าย เดาได้ว่าเทียบขนาดไฟล์โมเดล (ที่ context ค่าหนึ่ง) กับ VRAM และ RAM ที่ตรวจพบ ใกล้เคียงกับ `lms load --estimate-only <model>` ที่แสดงหน่วยความจำ GPU ที่คาดว่าจะใช้และคิดรวม `--context-length` กับ `--gpu` ด้วย (https://lmstudio.ai/docs/cli/local-models/load) แต่**ยังไม่มีหลักฐาน**ว่าป้ายใช้สูตรเดียวกับคำสั่งนี้
- **เรื่องที่เกี่ยวข้อง: Model loading guardrails** (ตั้งค่าใน Settings) [ยืนยันแล้วจากไฟล์แปล `settings.json`/`models.json`] มีระดับ OFF / Relaxed / Balanced / Strict / Custom (กำหนดเพดาน GB เองได้) ถ้าโมเดลใหญ่เกิน แอปจะไม่ยอมโหลด และบอกว่าถ้าแน่ใจให้กด Alt ค้างเพื่อโหลดต่อ ("hold Alt to load anyway") พร้อมเตือนว่าเครื่องอาจค้าง

## 4. การแนบ .docx / .pdf / .txt ในแชท: ใส่ทั้งฉบับหรือใช้ RAG

- เอกสารทางการ https://lmstudio.ai/docs/app/basics/rag บอกแค่ว่า "ถ้าเอกสารพอดีกับ context จะใส่ทั้งฉบับ ถ้ายาวมากจะใช้ RAG" ไม่ได้บอกตัวเลข
- **ตัวเลขจริงอยู่ในซอร์สของปลั๊กอิน RAG ที่ติดมากับแอป** `lmstudio/rag-v1` ("LM Studio's native RAG plugin, shipping built-in with the app") [ยืนยันแล้วจากซอร์ส]
  https://lmstudio.ai/lmstudio/rag-v1/files/src/promptPreprocessor.ts
  ```
  context ที่ยังว่าง = context length − token ที่แชทใช้ไปแล้ว
  งบ = floor(context ที่ยังว่าง × 0.7 × (1 − สัดส่วน context ที่ใช้ไปแล้ว))
  ถ้า token ของเอกสารทุกไฟล์ + token ของคำสั่ง > งบ  → ใช้ "retrieval" (RAG)
  ถ้าไม่เกิน                                        → ใช้ "inject-full-content" (ใส่ทั้งฉบับ)
  ```
  - ในแชทใหม่ เกณฑ์จะอยู่ที่ประมาณ **70% ของ context length** แต่ถ้าแชทยาวขึ้น งบจะลดลงเร็ว เพราะถูกหักสองชั้น
  - ตัวอย่าง: ถ้า context = 4096 เอกสารรวมคำสั่งต้องไม่เกินประมาณ 2,800 token ภาษาไทยใช้ token เยอะ เอกสาร 1–2 หน้าจึงอาจเกินแล้ว
- **ค่าที่ปรับได้มีแค่ 2 ตัว** (ใน `config.ts`) คือ `retrievalLimit` (จำนวนท่อนที่ดึงมา ค่าเริ่มต้น 3 ปรับได้ 1–10) และ `retrievalAffinityThreshold` (ความใกล้เคียงขั้นต่ำ ค่าเริ่มต้น 0.5) https://lmstudio.ai/lmstudio/rag-v1/files/src/config.ts
- **บังคับให้ใส่ทั้งฉบับตรงๆ ไม่ได้** เพราะไม่มีตัวเลือกนี้ ทางอ้อมคือเพิ่ม context length ตอนโหลดโมเดล (แต่จะใช้หน่วยความจำมากขึ้น) หรือเริ่มแชทใหม่ หรือคัดลอกข้อความมาวางในแชทเอง
- RAG ใช้โมเดล embedding ชื่อ `nomic-ai/nomic-embed-text-v1.5-GGUF` [ยืนยันแล้วจากซอร์ส] **[ยังไม่ยืนยัน]** ว่าดึงท่อนภาษาไทยได้แม่นแค่ไหน
- **ข้อจำกัดการแนบไฟล์** (จากไฟล์แปล `onboarding.json`): แนบได้ครั้งละไม่เกิน 5 ไฟล์ รวมไม่เกิน 30MB รองรับ PDF, DOCX, TXT, CSV [ยืนยันแล้ว แต่เป็นข้อความเก่าจากหน้าแนะนำ RAG อาจไม่ตรงกับ 0.4.26]
- **PDF ที่เป็นภาพสแกน / OCR** [ยังไม่ยืนยันแบบเป็นทางการ] ไม่มีคำว่า OCR ทั้งในเอกสาร ซอร์ส rag-v1 และ changelog ซอร์สอ่านไฟล์ผ่าน `parseDocument` และข้ามไฟล์รูปภาพไป จึงสรุปได้ว่าแอปไม่มี OCR ในตัว PDF สแกนจะได้ข้อความออกมาน้อยหรือไม่ได้เลย เรื่องนี้ตรงกับคำเตือนใน PRD §7 ควรทดสอบกับแอปจริงอีกครั้ง
- ต้องรู้ไว้ด้วยว่า: ซอร์สที่อ่านเป็นเวอร์ชันบน Hub (v7 แก้ล่าสุด 27 ก.พ.) **[ยังไม่ยืนยัน]** ว่าตรงกับที่ติดมาใน 0.4.26 ทุกบรรทัด

## 5. Local server (API แบบเดียวกับ OpenAI) สำหรับสคริปต์ทดสอบ

- **Endpoint** [ยืนยันแล้ว] base URL คือ `http://localhost:1234/v1` (พอร์ต 1234)
  - แบบ OpenAI: `GET /v1/models`, `POST /v1/chat/completions`, `/v1/completions`, `/v1/responses`, `/v1/embeddings` https://lmstudio.ai/docs/developer/openai-compat
  - API ของ LM Studio เอง: `POST /api/v1/chat` (เพิ่มมาใน 0.4.0) https://lmstudio.ai/docs/developer/rest/chat และของเดิม `/api/v0/*`
- **วิธีเปิด server** [ยืนยันแล้ว] https://lmstudio.ai/docs/developer/core/server
  - ในแอป: ไปที่แท็บ Developer แล้วเปิดสวิตช์ "Start server"
  - CLI: `lms server start` / `lms server stop` ถ้าไม่อยากเปิดหน้าต่างแอป ใช้ `lms daemon up` (llmster) แทน
- **โหลดโมเดลตามชื่อและ quantization ที่ต้องการ** [ยืนยันแล้ว]
  - ดาวน์โหลด: `lms get <ชื่อโมเดล>@q4_k_m` (ใส่ `-a` ถ้าอยากเลือก quantization เอง) https://lmstudio.ai/docs/cli/local-models/get
  - โหลด: `lms load <model_key> --context-length 8192 --gpu max --identifier test-model` ดู model_key ได้จาก `lms ls` https://lmstudio.ai/docs/cli/local-models/load
  - ตรวจว่าโหลดอะไรอยู่: `lms ps` / เลิกโหลด: `lms unload --all` / ดูหน่วยความจำที่จะใช้ก่อนโหลดจริง: `lms load --estimate-only <model_key>`
  - ใช้ `GET /api/v0/models/{model}` เช็กได้ว่าโหลด quant ไหนอยู่ (ฟิลด์ `quant`) และใช้ context เท่าไร (ฟิลด์ `context_length`)
- **ค่าเริ่มต้นตอนรันโมเดล**
  - ค่าเริ่มต้นแยกตามโมเดล: ตั้งได้ที่ My Models → ไอคอนเฟือง แอปจะใช้ค่านี้ทุกครั้งที่โหลด รวมถึงตอนโหลดด้วย `lms load` https://lmstudio.ai/docs/app/advanced/per-model
  - โมเดลในแคตตาล็อกใช้ `model.yaml` ซึ่งกำหนดค่า sampling มาให้เอง เช่น qwen3-8b ตั้ง topK=20 https://lmstudio.ai/docs/app/modelyaml
  - **context length เริ่มต้น** [ยังไม่ยืนยัน] เอกสารทางการไม่ได้บอกตัวเลข มีแหล่งภายนอก (issue ของ Zed) ที่เจอค่า 4096
  - เอกสาร chat-completions แนะนำให้ส่ง temperature, top_p และค่าอื่นๆ มาใน request เอง และไม่ได้บอกว่าถ้าไม่ส่งจะใช้ค่าอะไร
  - **ข้อแนะนำสำหรับ PRD §6.3**: กำหนด `temperature`, `top_p`, `top_k`, `max_tokens`, `seed` ใน request ทุกครั้ง และโหลดทุกโมเดลด้วย `--context-length` ค่าเดียวกัน แล้วบันทึกค่าทั้งหมดเปิดเผยไว้ ไม่ควรเขียนว่า "ใช้ค่าเริ่มต้นของ LM Studio" เพราะแต่ละโมเดลมีค่าเริ่มต้นไม่เหมือนกัน
- **response บอกความเร็วไหม** [ยืนยันแล้ว] `/api/v1/chat` ส่ง `stats` กลับมา ได้แก่ `tokens_per_second`, `time_to_first_token_seconds`, `input_tokens`, `total_output_tokens`, `reasoning_output_tokens`, `model_load_time_seconds` ส่วน `/api/v0/chat/completions` มี `tokens_per_second`, `time_to_first_token`, `generation_time` พร้อม `model_info.quant` และ `runtime`
  - `/v1/chat/completions` (แบบ OpenAI) **[ยังไม่ยืนยัน]** ว่ามีค่าความเร็วหรือไม่ น่าจะมีแค่ `usage` ตามรูปแบบมาตรฐาน ถ้าต้องการผลวัดความเร็ว ให้ใช้ `/api/v1/chat` หรือ `/api/v0/chat/completions`

## 6. ความต้องการขั้นต่ำบน Windows

https://lmstudio.ai/docs/app/system-requirements [ยืนยันแล้ว]
- รองรับทั้ง x64 และ ARM (Snapdragon X Elite)
- เครื่อง x64 **ต้องมี CPU ที่รองรับ AVX2** (เป็นข้อบังคับ)
- RAM: **แนะนำ 16GB ขึ้นไป** (เป็นคำแนะนำ ไม่ใช่ขั้นต่ำบังคับ)
- การ์ดจอ: แนะนำ VRAM แยก 4GB ขึ้นไป หน้านี้ไม่ได้ระบุยี่ห้อ
- engine ของแอปเป็น llama.cpp หลายแบบ ได้แก่ CPU-only, CUDA, Vulkan, ROCm (https://lmstudio.ai/blog/lmstudio-v0.3.9) จัดการ engine ได้ด้วย `Ctrl+Shift+R`
  - NVIDIA: ใช้ CUDA ถ้าเป็น RTX 50 ต้องใช้ไดรเวอร์ 551.61 ขึ้นไป (https://lmstudio.ai/blog/lmstudio-v0.3.15)
  - AMD บน Windows: ใช้ Vulkan ได้ ส่วนการ์ดจอในตัวจะถูกปิดไว้เป็นค่าเริ่มต้น (https://lmstudio.ai/blog/lmstudio-v0.3.14) **[ยังไม่ยืนยัน]** ว่ามี ROCm บน Windows หรือไม่ (เอกสารพูดถึงแต่ Linux)
  - Intel (Arc / การ์ดจอในตัว): **[ยังไม่ยืนยัน]** ไม่พบเอกสารทางการ น่าจะใช้ผ่าน Vulkan ได้

## 7. การติดต่อเน็ตและการใช้แบบออฟไลน์

- **ใช้ออฟไลน์ได้ทั้งหมดหลังดาวน์โหลดโมเดลแล้ว** [ยืนยันแล้ว] "LM Studio can operate entirely offline, just make sure to get some model files first." แชท แชทกับเอกสาร และ local server ใช้ได้โดยไม่ต้องต่อเน็ต https://lmstudio.ai/docs/app/offline
  - หมายเหตุ: RAG ต้องใช้โมเดล embedding (nomic) **[ยังไม่ยืนยัน]** ว่าติดมากับแอปเลยหรือต้องโหลดเพิ่ม ถ้าต้องโหลดเพิ่ม การแนบเอกสารยาวครั้งแรกตอนตัดเน็ตอาจไม่ทำงาน ต้องทดสอบ
- **สิ่งที่ต้องใช้เน็ต** [ยืนยันแล้ว] ค้นหาโมเดลในแท็บ Discover (เรียก huggingface.co), ดาวน์โหลดโมเดล, ดูสถิติล่าสุดในแคตตาล็อก, เช็กและดาวน์โหลด engine, **เช็กอัปเดตแอปทุกครั้งที่เปิดแอป** (Windows/macOS)
- **นโยบายความเป็นส่วนตัว (มีผล มิ.ย. 2026)** https://lmstudio.ai/app-privacy [ยืนยันแล้ว]
  - "the application does not include telemetry or user-specific tracking"
  - ตอนเช็กอัปเดตจะส่ง เวอร์ชันแอป ระบบปฏิบัติการ และ IP ออกไป
  - คำที่ค้นหาโมเดลจะถูกเก็บแบบไม่ระบุตัวตน
  - ถ้ารันโมเดลบนเครื่อง "none of your messages, chat histories, and documents are ever transmitted from your system" ข้อมูลจะออกจากเครื่องก็ต่อเมื่อซื้อฟีเจอร์คลาวด์ (เช่น ค้นเว็บ หรือโมเดลบนคลาวด์) **และ**เลือกใช้ฟีเจอร์นั้นเอง
  - ไม่มีตัวเลือกปิดการเช็กอัปเดต [ยังไม่ยืนยันว่าในแอปมีสวิตช์นี้หรือไม่]
- **ผลต่อถ้อยคำบนเว็บ**: "ประมวลผลบนเครื่องคุณ ลองตัดเน็ตดูได้เลย" ยังใช้ได้และตรงกับเอกสาร ควรเพิ่มคำเตือนสั้นๆ ว่า (1) แอปจะเช็กอัปเดตเมื่อเปิดแอปตอนต่อเน็ตอยู่ ซึ่งเป็นเรื่องปกติและไม่ได้ส่งเนื้อหาแชทออกไป และ (2) อย่าเปิดใช้ฟีเจอร์คลาวด์หรือค้นเว็บ (เป็นฟีเจอร์ที่เสียเงินและต้องเปิดเอง)
