# ร่าง concept: นโยบายบริษัทกับ AI ออฟไลน์

- สถานะ: ร่างที่ 1 รอ grill (2026-10-23)
- วันที่: 2026-10-22
- คำศัพท์ใช้ตาม [GLOSSARY.md](../GLOSSARY.md)
- **ข้อมูลกฎหมายและมาตรฐานทั้งหมดในร่างนี้ยังไม่ได้ค้นจากต้นฉบับ** ข้อที่อ้างมาตรฐานติดป้าย **[ยังไม่ยืนยัน]** ไว้ ต้องค้นก่อนเขียนเนื้อหาจริง

## 1. ปัญหาที่ส่วนนี้จะแก้

PRD §1 บอกไว้แล้วว่า "บริษัทจำนวนมากไม่อยากนำเอกสารขึ้น Cloud" แต่ในเว็บยังไม่มีส่วนไหนอธิบายเรื่องนี้ ผู้ใช้กลุ่มหลัก (พนักงานออฟฟิศมือใหม่ รวมถึง first jobber) ติดอยู่ 3 เรื่อง

1. ไม่เข้าใจว่าทำไมบริษัทห้ามใช้ AI บน cloud รู้แค่ว่า "ห้าม"
2. ไม่รู้ว่า AI ออฟไลน์ช่วยเรื่องนี้ได้แค่ไหน
3. ไม่รู้ว่าจะไปขออนุญาตฝ่าย IT ยังไง

## 2. สารหลัก (ประโยคเดียว)

> บริษัทห้ามเพราะข้อมูลจะออกไปอยู่บนเครื่องของคนอื่น AI ออฟไลน์ทำให้ข้อมูลอยู่บนเครื่องเรา แต่ก่อนลงโปรแกรมยังต้องขออนุญาต IT อยู่ดี และเว็บนี้ช่วยเตรียมเรื่องที่ต้องคุยกับ IT ให้

## 3. ขอบเขต

**จะพูด**
- เหตุผลที่บริษัทห้าม เขียนด้วยภาษาคนทั่วไป และอ้างมาตรฐานสั้นๆ
- AI ออฟไลน์แก้เรื่องอะไรได้ และเรื่องอะไรที่ยังไม่ได้แก้
- เช็กลิสต์และข้อความสำเร็จรูปสำหรับไปขออนุญาต IT

**จะไม่พูด**
- ไม่บอกว่าใช้ AI ออฟไลน์แล้วผ่านมาตรฐานหรือถูกกฎหมาย
- ไม่อธิบายเนื้อหามาตรฐานยาวๆ
- ไม่สอนวิธีเลี่ยงนโยบาย IT (เช่น ลงโปรแกรมแบบไม่ต้องขอสิทธิ์ admin) เพราะจะทำให้ผู้ใช้มีปัญหากับบริษัท และขัดกับจุดยืนของเว็บ
- ไม่ให้คำปรึกษาทางกฎหมาย

## 4. ทำไมบริษัทห้าม (ร่างเนื้อหา)

| เหตุผลที่คนอ่านเข้าใจได้ | กฎหรือมาตรฐานที่เกี่ยว | สถานะ |
|---|---|---|
| เอกสารมีข้อมูลลูกค้าหรือพนักงาน ถ้าส่งขึ้น cloud ต่างประเทศอาจผิดกฎหมาย | PDPA ส่วนที่ว่าด้วยการส่งข้อมูลส่วนบุคคลไปต่างประเทศ (น่าจะเป็นมาตรา 28–29) | [ยังไม่ยืนยัน] |
| เอกสารเป็นความลับของบริษัทหรือของลูกค้า (สัญญา, NDA, ราคา) | ISO/IEC 27001 เรื่องการจัดระดับชั้นข้อมูล การใช้บริการ cloud และการป้องกันข้อมูลรั่ว (ต้องหาเลข control ที่ตรง) | [ยังไม่ยืนยัน] |
| ไม่รู้ว่าผู้ให้บริการเอาข้อมูลไปฝึกโมเดลหรือเก็บไว้นานแค่ไหน | เงื่อนไขการใช้ (terms) ของผู้ให้บริการแต่ละราย | [ยังไม่ยืนยัน] |
| บริษัทเริ่มมีระบบบริหารจัดการ AI ของตัวเอง | ISO/IEC 42001 | [ยังไม่ยืนยัน] |
| ธุรกิจบางประเภทมีกฎเฉพาะ (ธนาคาร, โรงพยาบาล, หน่วยงานรัฐ) | ประกาศของหน่วยงานกำกับ เช่น ธปท., ก.ล.ต. | [ยังไม่ยืนยัน] ต้องตัดสินใจว่าจะพูดถึงไหม |

**CMMI: ตัดออก** เพราะเป็นมาตรฐานวัดความพร้อมของกระบวนการพัฒนา ไม่ได้กำหนดว่าข้อมูลขึ้น cloud ได้หรือไม่ ถ้าใส่ไปจะดูเหมือนยกชื่อมาตรฐานมาให้ดูน่าเชื่อถือเฉยๆ

## 5. AI ออฟไลน์แก้อะไรได้ และอะไรที่ยังไม่ได้แก้

| แก้ได้ | ยังไม่ได้แก้ |
|---|---|
| ข้อมูลที่พิมพ์หรือวางให้โมเดลอยู่บนเครื่องเรา ไม่ส่งไปที่อื่น | การลงโปรแกรมเองอาจผิดนโยบาย IT ต้องขออนุญาตก่อน |
| พิสูจน์เองได้ด้วยการตัดเน็ตแล้วลองถาม (ขั้น ⑥ ของวิซาร์ด) | ไลเซนส์ของโมเดลบางตัวมีเงื่อนไขเรื่องการใช้เชิงพาณิชย์ ต้องเช็กทีละตัว |
| ไม่ต้องสมัครบัญชีหรือส่งข้อมูลให้ผู้ให้บริการ | ตัวแอปยังต่อเน็ตตอนโหลดโมเดลหรืออัปเดต ต้องเช็กว่าส่งข้อมูลอะไรออกไปบ้าง [ยังไม่ยืนยัน ดู docs/research/lm-studio.md เรื่อง privacy] |
| | ถ้าโน้ตบุ๊กหาย ข้อมูลในเครื่องก็หายไปด้วย ความปลอดภัยของเครื่องยังเป็นเรื่องของบริษัท |
| | AI ตอบผิดได้ ผู้ใช้ยังต้องตรวจคำตอบเอง |

## 6. เช็กลิสต์ขออนุญาต IT (ร่าง)

สิ่งที่ผู้ใช้ควรเตรียมไปคุยกับ IT

- ชื่อแอป ลิงก์ดาวน์โหลด และเงื่อนไขการใช้ในงาน (LM Studio อนุญาตให้ใช้ในธุรกิจภายใน ตาม docs/research/lm-studio.md ข้อ 6)
- ชื่อโมเดลที่จะใช้และไลเซนส์ของโมเดลนั้น
- ยืนยันว่าทำงานบนเครื่อง และทดสอบได้ด้วยการตัดเน็ต
- จะใช้กับข้อมูลระดับไหน (เช่น เอกสารทั่วไปเท่านั้น หรือรวมถึงข้อมูลลับด้วย)
- พื้นที่ที่ต้องใช้ในเครื่องและสเปกขั้นต่ำ
- ใครจะเป็นคนดูแลเรื่องการอัปเดต

รูปแบบที่คิดไว้: ข้อความอีเมลสำเร็จรูปที่กดคัดลอกได้ เติมชื่อโมเดลและสเปกจากผลของวิซาร์ดให้อัตโนมัติ

**กรณีที่บริษัทไม่อนุญาตให้ลงโปรแกรมเลย:** ห้ามจบที่ทางตัน (หลักเดียวกับกรณี RAM 4GB ใน PRD §4) ทางไปต่อที่เป็นไปได้ เช่น เสนอให้บริษัทจัดเครื่องหรือจัดการติดตั้งให้ หรือลองใช้กับเครื่องส่วนตัวด้วยเอกสารที่ไม่ใช่ข้อมูลลับก่อน

## 7. จะวางไว้ตรงไหนในเว็บ

- **หน้าแรก:** ส่วนสั้น 2–3 บรรทัด ใช้ประโยคตามข้อ 2 แล้วลิงก์ไปหน้าเต็ม
- **หน้าเต็ม:** หน้าใหม่ (ชื่อหน้ายังไม่ได้ตั้ง) มีเนื้อหาข้อ 4–6
- **วิซาร์ด:** ขั้น ③ เพิ่มข้อ "ขออนุญาต IT แล้วหรือยัง" ในเช็กลิสต์ก่อนโหลด แล้วลิงก์ไปข้อความสำเร็จรูป

## 8. คำถามสำหรับ grill พรุ่งนี้

1. ต้องเพิ่ม first jobber ใน PRD §3 แยกเป็นกลุ่มของตัวเองไหม หรือนับรวมอยู่ใน "พนักงานออฟฟิศมือใหม่"
2. ควรลงรายละเอียดเรื่องมาตรฐานแค่ไหน ใส่แค่ชื่อพร้อมลิงก์ หรืออธิบายด้วยว่าแต่ละข้อเกี่ยวกับเรื่องนี้อย่างไร
3. จะพูดถึงกฎเฉพาะของแต่ละอุตสาหกรรม (ธนาคาร, โรงพยาบาล, รัฐ) ไหม
4. เว็บต้องมีข้อความปฏิเสธความรับผิด (disclaimer) ทางกฎหมายมากแค่ไหน
5. ข้อความขออนุญาต IT จะทำเป็นอีเมลให้คัดลอก หรือเป็นไฟล์ให้ดาวน์โหลด
6. ถ้าบริษัทห้ามลงโปรแกรมเลย เว็บจะบอกผู้ใช้ว่าอะไร
7. หน้าภาษาอังกฤษ (/en/) ควรพูดถึง PDPA ไหม หรือเขียนให้เป็นกลางไม่ผูกกับประเทศ
8. ต้องเพิ่มคำใหม่ใน GLOSSARY ไหม (เช่น "นโยบายบริษัท", "ฝ่าย IT")
9. เรื่องนี้ต้องแก้ PRD ข้อไหนบ้าง

## 9. ข้อมูลที่ต้องค้นก่อนเขียนเนื้อหาจริง

- PDPA มาตราที่ว่าด้วยการส่งข้อมูลไปต่างประเทศ (ค้นจากตัวบทในราชกิจจาฯ)
- ISO/IEC 27001:2022 ข้อ control ที่เกี่ยวกับ cloud, การจัดชั้นข้อมูล และการป้องกันข้อมูลรั่ว
- ISO/IEC 42001 ขอบเขตโดยย่อ
- ไลเซนส์ของโมเดลที่เว็บแนะนำ ว่าใช้เชิงพาณิชย์ได้ไหม
- แอป LM Studio ส่งข้อมูลอะไรออกจากเครื่องบ้าง (เช็กกับข้อมูลใน docs/research/lm-studio.md)
